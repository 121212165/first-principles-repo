# 证伪挑战协议(Falsify Challenge Protocol)

**本协议是本仓库最核心的活机制**——它让"第一性原理清单"从静态文档变成**持续被攻击、持续被修正**的活体知识。

---

## 1. 什么是证伪挑战

任何人对任何 `axiom` 提出质疑:**"这条其实可以被 X 推导,不配当公设"**。
挑战成功后,该条目被降级(theorem/fact/hypothesis),词表同步更新——**整条知识的地位被永久改写**。

这不是攻击,是本仓库存在的意义:穷尽的唯一方式,是让每条公设都接受"被杀死"的检验。

---

## 2. 挑战的三种形式

| 形式 | 目标 | 产出 |
|---|---|---|
| **推导挑战** | 证明某 axiom 可由更底层原理推导 | 条目降级为 theorem + 补 `derived_from` |
| **还原挑战** | 证明某 axiom 只是某机制的展开(原理上可还原) | 条目降级为 theorem/fact |
| **事实挑战** | 证明某 axiom 实为观测事实/历史偶然 | 条目降级为 fact |

## 3. 挑战流程(如何在 GitHub 上执行)

```
1. 开 issue,标题: [证伪挑战] L2-014 量子纠缠 —— 可由 L2-010 推导
2. issue 正文必须包含"推导链":从更底层公设到目标条目的推理步骤(至少 3 步,可符号化)
3. 维护者(或任何评审人)24h 内响应:接受 / 驳回 / 要求补充
4. 若接受 → 挑战者(或维护者)开 PR 修改条目:
     - status: axiom -> theorem
     - 补 derived_from(指向推导源)
     - 补 downgrade_to(记录挑战轨迹)
     - 同时把该主题加入 rules/peeling-audit.yaml 的 peel 词表
       (防止后人再把它当 axiom 提交)
5. 合并后,挑战者在 README 的"证伪挑战记录"登记:
     [x] L2-014 纠缠 → theorem (2026-08-06, 挑战者 @xxx, 推导自 L2-010)
```

## 4. 推导链的最低标准(不接受"感觉能推导")

- ❌ "这个概念物理上可还原为量子力学" → 太笼统
- ✅ 至少给出:从哪条公设 → 经过什么定理/步骤 → 得到目标陈述
  - 例:纠缠 = 张量积结构公设(态空间)⇒ 可分态判别(施密特分解)⇒ 贝尔不等式的违反。

**没有推导链的挑战,不算挑战,是闲聊。** 闲聊请去 Discussions。

## 5. 挑战成功的奖励

- 你的名字永久进入 `docs/FALSIFY.md` 的挑战记录表(荣誉)。
- 该主题进入剥离词表,成为后续所有提交者的"雷区"。
- 整个仓库的 axiom 总数 -1——**这是对穷尽性最实在的贡献**。

## 6. 挑战失败 ≠ 你的错

被驳回的挑战也记录了"防守论证"——它让 `peel_evidence` 更强。
失败挑战沉淀为"边缘案例文档"(docs/EDGE-CASES.md),供后人参考。

## 7. 特别说明:哪些条目"不可挑战"(不是不能,是挑战目标不同)

- **theorem/fact/hypothesis**:它们已非公设,挑战它们意义不大(除非你觉得它们的 `derived_from` 指错了,那也是有效挑战——目标是修正推导图)。
- **meta 元公设**:挑战它们=挑战整个框架的哲学前提,请开"元讨论"issue,不走本协议。
- **最终底线 9 条**(L2 物理经验公设、L5 感受质、L10 强涌现):可以挑战,但请做好心理准备——它们已经历四轮审计幸存,你需要真正新的论证,不是重复已有反驳。

## 8. 自动化的配合

- **falsify.py** 每次 PR 都会跑剥离审计——它负责"机器能发现的挑战"(词表命中、重叠、错位)。
- **人类评审**(REVIEW.md)负责"机器发现不了的挑战"(语义推导、概念还原)。
- **分工原则**:机器查形式,人查本质。
