# 评审清单(Review Checklist)

评审人的使命:**不是确认"这条重要",而是尝试杀死它。**
一条公设只有在"杀不死"时才配叫第一性原理。

---

## 评审流程

1. 阅读条目全文(front matter + 正文)
2. 运行/阅读 CI 报告(硬校验 + 证伪引擎待审清单)
3. 按下表逐项检查
4. 在 PR 中给出裁决:✅ approve / ❌ request-changes / 🤔 讨论
5. 若你的质疑站得住,按 FALSIFY.md 走"证伪挑战"

---

## 检查清单(每条 axiom 逐项过)

### A. 向下还原(最重要)

- [ ] **推导搜索**:能否找到一条更底层原理,严格推导出本条?找 10 分钟,找不到才放过。
  - 提示:问"它的前置假设是什么?""它是否是某条量子公设/热力学定律/选择公理的展开?"
- [ ] **剥离词表**:是否命中 `rules/peeling-audit.yaml` 本层级的 peel 主题?若命中,贡献者的 `peel_evidence` 自辩是否成立?
- [ ] **同层重复**:是否与同层另一条 axiom 语义重叠?(falsify.py 会做粗检,人工做精检)
- [ ] **层间错位**:主题是否属于别的层级?(如把"感受质"写进 L2,把"价格"写进 L4)

### B. 涌现层独立性

- [ ] **不可还原性**:向上看,本条是否表达了该层级独有的、下层没有的新东西?
  - 例:L4 自然选择 → 化学里没有"选择";L7 价格 → 物理里没有"价格"。
- [ ] **概念自治**:本条依赖的概念是否是该层级不可消除的?(如"键"之于化学,"均衡"之于经济学)

### C. 形式质量

- [ ] `statement` 是否一句话、可否证伪(或明确是公设所以不可证伪)?
- [ ] `boundary` 是否诚实标注了失效条件?(没有边界 = 红牌,必然写错了)
- [ ] `peel_evidence` 是否真的在反驳还原,而不是复述重要性?
  - ⚠️ 常见作弊:把"这条很重要"当证据。重要 ≠ 不可还原。
- [ ] 引用关系(derived_from/derives)是否双向一致、无环?

### D. 穷尽性(评审的副产物)

- [ ] 该层级 `must_cover` 主题是否都已覆盖?(falsify.py 的 misplaced 项)
- [ ] 该层级是否有明显缺失的底层公设?(评审人可提 issue 补录)

---

## 裁决标准

| 裁决 | 条件 |
|---|---|
| ✅ approve | 全部 A/B 通过,C 小瑕疵可容忍 |
| ❌ request-changes | A 中任一项不通过(可推导/重复/错位),或 C 中 peel_evidence 作弊 |
| 🤔 讨论 | 边界争议(如该不该算公设、层级归属两可) |

## 评审人自检

- [ ] 我没有因为"这条我听说过/很重要"而放水——**熟悉感是最大的评审盲区**
- [ ] 我真的尝试推导过它(哪怕失败了)
- [ ] 我的评论具体到"推导链"或"失效场景",而不是泛泛的"不错"

---

## 对"定理区"条目的评审(宽松一些)

theorem/fact/hypothesis 不是本仓库的竞争力,评审重点是:
- [ ] `derived_from` 指向真实存在的公设
- [ ] `downgrade_to` 交代了审计轨迹(防止有人把公设降级后忘掉)
- [ ] 不占用 axiom 的配额意识:定理区不该无限膨胀(建议定理:公设 ≈ 1:3 封顶)
