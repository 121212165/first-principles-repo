# 实战攻防测试记录(Attack-Test Log)

> 这个仓库的门禁系统,是拿**真实的陌生 AI 提交**打出来的。本文记录每一次"无预谋攻击"与系统反应——这是门禁可信度的证据链。

---

## 测试方法

**陌生 AI 无预谋提交**:在一个与仓库完全隔离的外部环境,给 AI 一个极简任务("向这个仓库提交 7 条跨学科第一性原理"),明确要求**不读取仓库任何规范文件**。AI 凭直觉决定:文件放哪、叫什么、什么格式。这个流程模拟最危险的真实场景——一个不了解规则的贡献者,绕过所有约定直接提交。

| 要素 | 说明 |
|---|---|
| 提交方 | 外部 AI(无仓库上下文) |
| 通道 | GitHub API(blob → tree → commit → branch → PR) |
| 约束 | 禁止读 README / CONTRIBUTING / 目录结构 |
| 判定 | CI 三道门禁 + 人工裁判 |

---

## 第一轮(PR#1 · 2026-08-07):暴露结构盲区

**攻击**:文件放 `stranger/first-principles.md`(刻意逃逸 `principles/`),宣称 7 条原理。

**系统反应**:

| 门禁 | 结果 |
|---|---|
| 硬校验(validate) | ✅ pass —— **假绿灯!** |
| 证伪引擎(falsify) | ✅ pass —— 假绿灯(它根本没看到这个文件) |
| 门禁回归 | ✅ pass |
| **综合** | **CI 全绿 = 内容零审查通过** |

**暴露的漏洞**:`validate.py` / `falsify.py` 只扫描 `principles/` 目录,任何放在其他目录的提交完全绕过引擎。CI 绿灯不代表内容合格——**它代表内容根本没被看见**。

**修复**:validate.py 新增**全仓 .md 扫描**——`principles/` 之外的任何 .md 一律硬报错(目录逃逸拦截);`principles/` 下的非层级子目录同样拦截。回归测试新增 2 用例固化。

**另修复**:CI 评论 job 变量名 bug(`hard_exit` 大小写不一致,导致 PR 评论误报)。

---

## 第二轮(PR#2 · 2026-08-12):验证修复生效

**攻击**:完全复刻第一轮——`stranger/first-principles.md`,目录逃逸 + 真实内容(7 条原理)。

**系统反应**:

| 门禁 | 结果 |
|---|---|
| 硬校验(validate) | ❌ **failure —— 真拦截!** |
| 证伪引擎(falsify) | ✅ pass(principles/ 未被污染) |
| 门禁回归 | ✅ pass |

**拦截原文**(CI 日志):
```
[FAIL] stranger/first-principles.md: 位于非法目录 'stranger',原理条目必须放在
        principles/L{n}-* 下;引擎不扫描该目录,内容将绕过剥离审计——请移动或删除
```

**结论**:同一攻击,第一轮"全绿",第二轮"标红"——结构盲区修复在真实环境验证生效。

## 第三轮(进行中):诚邀你的参与

想挑战?我们**欢迎**你绕过这套门禁。方法:

1. 在一个全新环境(无本仓库上下文)发起一个 PR——提交什么内容都行,位置、格式全凭直觉;
2. 把 PR 链接发到 Issues;
3. 我们会把 CI 结果和裁判结论回给你。

如果你成功让"内容没被正确拦截"的 PR 合并/通过,你就是这个仓库的**头号功臣**——那是我们下一个要修的漏洞。挑战者自动进入 CONTRIBUTORS.md 攻防记录。

## 门禁当前能力边界(诚实清单)

| 能拦 | 不能拦(靠人类评审) |
|---|---|
| 目录逃逸、格式错误、缺 front matter | 强语义伪造(AI 编造来源文献) |
| 定理冒充公设(剥离词表命中) | 词表未收录的新定理伪装 |
| 条目重叠、引用悬空 | 学术立场分歧(见 docs/词表争议记录.md D-001) |

机器管"结构与词表",人类管"语义"——这是三层防线的分工,不是缺陷。
